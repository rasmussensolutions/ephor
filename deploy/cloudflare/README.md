# Cloudflare Workers + D1

One Worker serves the dashboard assets and `/api/*`; no VPS or separate Node
server is required. D1 holds users, sessions, passkeys, policy state, audit events,
and rate limits. The landing page remains a separate frontend.

## Deploy in your browser

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https%3A%2F%2Fgithub.com%2Frasmussensolutions%2Fephor)

1. Click **Deploy to Cloudflare** and connect your Cloudflare and GitHub accounts.
   Cloudflare copies the entire repository into your account. Keep the repository
   root selected so the dashboard and shared packages are included.
2. Choose your Worker and database names. Fill in the deployment settings:

   | Setting              | What to enter                                                                                                                                                                                                                             |
   | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | `EPHOR_ORIGIN`       | Your final HTTPS panel address, without a trailing slash. For example, `https://ephor.your-subdomain.workers.dev`. Find your account's workers.dev subdomain in **Workers & Pages**. The first part must match the Worker name you chose. |
   | `BETTER_AUTH_SECRET` | A new random 64-character password generated by your password manager. Keep this value stable on future deployments.                                                                                                                      |
   | `EPHOR_SETUP_CODE`   | A separate random password of 32–128 characters. Save it for the Ephor setup screen.                                                                                                                                                      |

   Cloudflare stores the two secrets as Worker secrets. Use the provided official
   release URL and public key. Accept the detected `bun run build` and
   `bun run deploy` commands. Turn off **Enable Preview builds**, since owner
   passkeys use your final panel address. Cloudflare creates and binds the D1 database.
3. Click **Deploy**. The build downloads both published Linux daemon binaries,
   checks the pinned release manifest and binary checksums, builds the dashboard,
   applies D1 migrations, and deploys the Worker and assets.
4. Open your panel, enter your name and saved setup code, and create a passkey.
   In **Security**, save recovery codes and register a second passkey.

The setup code is consumed atomically when you submit it. Finish registering your
passkey within ten minutes. If you lose that browser session or the enrollment
expires, generate a new setup code and replace `EPHOR_SETUP_CODE` under the
Worker's **Settings → Variables and Secrets**, then deploy the change. This can
restart setup only while the panel has no configured owner. Once registered,
remove `EPHOR_SETUP_CODE` from the Worker secrets. Use saved recovery codes for
account recovery after setup.

For a custom domain, add it under **Settings → Domains & Routes** and set
`EPHOR_ORIGIN` to that exact HTTPS address in your copied repository's root
`wrangler.jsonc` before registering your passkey. Committing the change in GitHub
triggers another Cloudflare build. Passkeys are bound to the chosen hostname.

The root `wrangler.jsonc` is the browser deployment template. Cloudflare writes
your resource identifiers into your copy. The configuration under `apps/worker`
supports the separate local/manual workflow below. The template uses the `DB`
binding for migrations so changing the database name in the form works.

Worker builds use `WORKERS_CI=1` to select `build:cloudflare`. The daemon version
and manifest checksum are pinned in `scripts/download-daemon.ts`. This build uses
published release assets (currently daemon `0.2.2`, with unified maintenance) and requires no Docker or Rust toolchain. The daemon
download files are generated during every build and included in the deployed
dashboard assets. Further pushes to your copied repository rebuild the panel and
apply pending migrations while preserving the configured owner.

After deployment, `/health` should return `{"status":"ok","service":"ephor-api"}`,
and `/daemon/manifest.json` should contain the bundled daemon version and both
architecture checksums. Add a machine in Ephor to get its VPS enrollment command.

See [Cloudflare's deploy-button documentation](https://developers.cloudflare.com/workers/platform/deploy-buttons/)
for account connection and automatic resource provisioning.

## Updating your panel

Open **Updates** in Ephor, connect the dedicated Updates GitHub App to your
deployment repository, and select **Cloudflare Workers → My host deploys GitHub
pushes**. Prepare, review, and install updates from the panel. Workers Builds must
use the default/production branch with preview builds disabled.

The GitHub **Actions → Update Ephor** workflow remains available as an alternative.
See the [panel update guide](../../docs/panel-updates.md) for setup, backups, and
the one-time workflow upgrade needed by older installations.

## Local development

```sh
bun install --frozen-lockfile
bun run --filter @ephor/dashboard build
# Copy apps/worker/.dev.vars.example to .dev.vars and set a random auth secret:
openssl rand -hex 32
bun run auth:admin migrate --worker
bun run auth:admin setup --worker
bun run dev:worker
```

Open `http://localhost:8787` and use the printed setup code. No Cloudflare account
is needed for local D1. A frontend change needs a rebuild, or use the dashboard's
Vite dev server with `EPHOR_API_URL=http://localhost:8787` and set the Worker's
`EPHOR_ORIGIN=http://localhost:3000` for that development arrangement.

## Deploy your installation

These commands create/deploy resources only when you run them:

```sh
bun run --filter @ephor/worker exec:wrangler d1 create ephor
```

Put the returned database ID in `apps/worker/wrangler.jsonc`. Set `EPHOR_ORIGIN`
to the final public HTTPS origin, configure its Worker route/custom domain, then:

```sh
bun run --filter @ephor/worker exec:wrangler secret put BETTER_AUTH_SECRET
bun run auth:admin migrate --worker --remote
bun run --filter @ephor/dashboard build
bun run --filter @ephor/worker exec:wrangler deploy
bun run auth:admin setup --worker --remote
```

Use a secret generated by `openssl rand -hex 32`. Never commit it or put it in
`vars`. D1 schema migrations and the application version must be deployed together.
The placeholder database ID intentionally requires an operator's configuration
before a real deployment. `bun run --filter @ephor/worker build` is a dry run.

Run `auth:admin cleanup --worker --remote` periodically. Back up D1 and the secret.
See [authentication](../../docs/authentication.md) for recovery and security details.

## Machine enrollment

Browser deployments include the daemon binaries and apply all migrations
automatically. For a manual deployment, run `bun run build:cloudflare` to download
the verified release binaries and build the dashboard, or use `bun run bundle:daemon`
on a build machine with Docker to build the daemon from source. Include the generated
`apps/dashboard/public/daemon/` artifacts in your deployed assets and apply the D1
migrations. The panel must have a public HTTPS origin; `/api/*` and
`/daemon/*` must be reachable by the VPS. See [connecting machines](../../docs/machines.md).
